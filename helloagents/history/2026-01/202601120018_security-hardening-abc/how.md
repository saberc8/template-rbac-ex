# 技术设计: 安全加固与分页优化（A+B+C）

## 技术方案
### 核心技术
- Go + Gin 中间件
- `database/sql` 参数化查询
- 环境变量配置校验

### 实现要点
- 日志中间件：
  - 对 `Authorization` 等敏感 header 脱敏；
  - 对请求/响应 body 做最大字节数限制与截断；
  - 对敏感路径（如 `/auth/login`）默认跳过 body 记录；
  - 避免读取超大 body 导致内存占用过高。
- 启动配置：
  - 移除 `main.go` 中默认 RSA 私钥/JWT secret；
  - 启动时缺失则直接 `log.Fatalf` 退出。
- 字典项分页：
  - 采用 SQL `WHERE` + `LIMIT/OFFSET` + `COUNT(*)`；
  - 过滤条件（`dictId/description/status`）在 SQL 层实现。

## 架构决策 ADR
### ADR-001: 系统日志默认脱敏与截断
**上下文:** `sys_log` 记录请求/响应体可能包含 token、密码、验证码等敏感信息。
**决策:** 默认对敏感头脱敏；对敏感路径跳过 body；对 body 设置上限并截断。
**理由:** 安全优先，降低泄露风险，同时保留必要审计字段。
**替代方案:** 全量记录 body → 拒绝原因: 泄露风险与存储/性能成本过高。
**影响:** 排障信息减少，需要通过日志白名单与上限配置平衡。

### ADR-002: 禁止内置默认密钥并强制 env 校验
**上下文:** 入口中存在默认密钥/私钥常量，风险较高。
**决策:** 删除默认值；缺失关键 env 时启动失败。
**理由:** 防止误用进入生产环境，符合安全基线。
**替代方案:** 保留默认值但仅用于开发 → 拒绝原因: 难以确保不会被复制到生产。
**影响:** 本地启动需显式配置环境变量。

### ADR-003: 列表分页下推到 SQL
**上下文:** 字典项分页目前是全量查询后内存分页，数据量上升会导致性能问题。
**决策:** DB 层完成过滤/分页/total 统计。
**理由:** 性能与资源占用更可控，语义更清晰。
**替代方案:** 继续内存分页 → 拒绝原因: 性能不可扩展。
**影响:** SQL 更复杂，需要确保参数化与索引合理。

## 安全与性能
- **安全:** 不落库敏感信息；启动强制校验密钥；避免超大 body 读入内存。
- **性能:** 分页下推到 DB；日志 body 截断减少 IO 与存储。

## 测试与部署
- **测试:** `go test ./...`；手工回归：登录、字典项分页、系统日志写入。
- **部署:** 更新环境变量配置（必须提供 `AUTH_RSA_PRIVATE_KEY`、`AUTH_JWT_SECRET`）。
